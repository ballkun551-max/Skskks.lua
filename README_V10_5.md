# BALL KUN AI FARM V10.5 — README

V9 เป็นฐานหลัก (ระบบเดิมอยู่ครบ) + ต่อเติมระบบจาก V10.1 ในไฟล์เดียว
**สถานะ: ยังไม่ได้ทดสอบในเกมจริง** ดูรายงานเปรียบเทียบสำหรับสิ่งที่ตรวจแล้วและยังไม่ได้ตรวจ

## ติดตั้ง
1. วาง `BALL_KUN_AI_FARM_V10_5.lua` ในโฟลเดอร์ workspace ของตัวรัน
2. รัน `BALL_KUN_AI_FARM_V10_5_Loader.lua` (หรือรันไฟล์หลักตรง ๆ ก็ได้)
3. เปิด/ปิดหน้าต่าง: `RightControl` หรือปุ่ม BK | สั่งผ่านโค้ด: `BK("สแกนทั้งหมด")` | API: `getgenv().BALLKUN_V102`

## UI (หน้าต่างเดียว 8 แท็บ)
Dashboard · Scanner · Manual Learning · AI Analyzer · Session Manager · Replay · Settings · Logs
หน้าเดิมของ V9 ทั้ง 10 หน้ายังอยู่ เข้าได้จากปุ่มนำทางในแท็บ Scanner / AI Analyzer / Settings / Dashboard

## ปุ่มหลัก
START SCAN · START RECORDING · PAUSE · RESUME · STOP RECORDING · SAVE SESSION · LOAD SESSION · ANALYZE DATA

- START SCAN รันเฉพาะ Scanner ที่เปิดสวิตช์ไว้ (อ่านอย่างเดียว) ไม่ใช่ Auto Dump ที่เดินตัวละคร
- START RECORDING: ช่อง "ID session" ว่าง = เริ่มใหม่ / ใส่ ID = บันทึกต่อจาก session เดิม
- LOAD SESSION: ช่อง ID ว่าง = โหลดอันล่าสุดของแมพนี้

| AI Analyzer | วิเคราะห์อัตโนมัติเมื่อหยุดบันทึก และเปิดปุ่ม ANALYZE / Farm Plan / ความสอดคล้อง |

## ข้อมูลสามประเภท (แยกชัดในรายงาน)
- **ยืนยัน (เกม)**: เหตุการณ์ที่ตรวจจับได้จริง เช่น ProximityPrompt, ClickDetector, SeatPart, ค่า leaderstats, ตัวละครตาย
- **ผู้เล่นป้อน**: อาชีพ ชื่อภารกิจ ผลสำเร็จ/ล้มเหลว ข้อผิดพลาดที่กดบันทึกเอง
- **ยังไม่ยืนยัน (อนุมาน)**: เช่น ลำดับขั้นตอนเป็นลำดับเวลา ไม่ใช่ลำดับที่เกมกำหนด

## Multi Map
- ตรวจ `game.PlaceId` ตอนเริ่ม: แมพใหม่สร้าง `BALL_KUN_AI_Dump/<PlaceId>/map_db.json` อัตโนมัติ
- ทุกการอ่าน/เขียน session ผูกกับ PlaceId ปัจจุบัน; session ต่าง PlaceId ถูกปฏิเสธทั้งตอน Load / Import / วิเคราะห์

## ความปลอดภัย
- ไม่สุ่มชื่อ Remote / ไม่เรียก FireServer-InvokeServer จากระบบบันทึกและ Replay
- Recorder ไม่กดปุ่ม ไม่เดินตัวละคร ไม่สร้างผลลัพธ์เอง
- Replay เป็น Simulation เท่านั้น (`Replay.execute` ปิดไว้เสมอ)
- ปุ่ม ⚡ Auto Dump ของ V9 (หน้า "ศูนย์ควบคุม V9") ยังเป็นพฤติกรรมเดิมของ V9 ที่เดินสำรวจและคลิก UI — แยกจากระบบบันทึก

## ไฟล์ตั้งค่าที่ใช้ร่วมกัน
- `BALL_KUN_AI_Dump/v102_settings.json` เป็นไฟล์ร่วม (ชื่อ v102 คงไว้เพื่อความเข้ากันได้) **V10.5 เขียนค่าใหม่ทับไฟล์นี้เมื่อเปลี่ยนสวิตช์** แม้ไฟล์ Lua V10.2 เดิมจะไม่ถูกแก้ แต่ค่าที่ V10.2 อ่านอาจเปลี่ยน
- ถ้าต้องการกลับไปใช้ค่าเดิม ให้สำรองไฟล์นี้ก่อนรัน V10.5

## การแก้ไขล่าสุดใน V10.5
- ID session ใหม่เป็น `YYYYMMDD_HHMMSS_<8 ตัวสุ่ม>` และตรวจว่าไม่มีไฟล์ชื่อนี้ก่อนใช้
- START RECORDING เซฟทันที ถ้าเซฟไม่สำเร็จจะเตือนและยังบันทึกต่อในหน่วยความจำ
- ป้ายเวอร์ชันบน UI และรายงานทดสอบอ่านจากตัวแปรเวอร์ชัน
- Loader ทำงานได้เมื่อไม่มี `debug.traceback` และล้างสถานะกำลังโหลดเมื่อขั้นอ่าน/คอมไพล์ผิดพลาด
- ยังไม่ได้ทดสอบในเกมจริง

## ข้อจำกัดที่ทราบ
- ยังไม่ได้รันในเกมจริง ต้องทดสอบด้วยปุ่ม RUN TESTS (แท็บ Settings) และเล่นจริงหนึ่งรอบ
- V9 ยังไม่มี Shop Scanner (แท็บ Shop แสดงว่ายังไม่สร้าง) — ไม่ได้อยู่ในขอบเขตงานนี้
- "ผลลัพธ์ที่ตรวจสอบได้" ทำได้เฉพาะแมพที่มี `leaderstats` ของผู้เล่น
- Session.list อ่านสูงสุด 60 รายการล่าสุด; เพดานต่อ session: 20,000 จุด / 5,000 เหตุการณ์

## ส่วนที่ 3 — Interaction Recorder v2 (ใหม่ใน V10.4)
| ประเภท | ตรวจจับอะไร | ฟิลด์สำคัญ |
|---|---|---|
| Prompt | ProximityPrompt ที่ผู้เล่นกดเอง, ถือค้าง, **ปล่อยก่อนครบเวลา** (เป็นเหตุการณ์ `interaction_abort` ไม่นับเป็นขั้นตอน) | hold, key, held, dist |
| Click | ClickDetector **ซ้ายและขวา** | button, maxDist, dist |
| Tool | ถือ / เก็บ / ใช้ (`tool_use` บันทึกทุก 2 วิ ที่เหลือนับเป็นซ้ำ) | at, seated |
| ปุ่ม UI | TextButton / ImageButton ที่ผู้เล่นกด (ยกเว้น UI ของ BALL KUN เอง) สูงสุด 600 ปุ่มที่ติดตามพร้อมกัน ปุ่มที่ถูกลบคืนโควตาอัตโนมัติ | object (ข้อความปุ่ม), screen, at |

- **ไม่บันทึก**: ข้อความที่พิมพ์ใน TextBox/แชต, ปุ่มคีย์บอร์ดทั่วไป, การเรียก Remote — ไม่มีการกดหรือเดินแทนผู้เล่น
- **แยกข้อมูลจริงกับที่คำนวณ**: `src="game"` = event ที่ตรวจจับได้จริงฝั่งไคลเอนต์; `held`/`dist`/`interaction_abort` = คำนวณฝั่งไคลเอนต์ และรายงาน AI แสดง abort ในหมวด "ยังไม่ยืนยัน"
- **Analyzer / Farm Plan**: นับแยกตามประเภท, เตือนเมื่อสวิตช์ย่อยปิดตอนบันทึก, ขั้นตอน tool/ui เข้า Farm Plan ได้ (ไม่มีพิกัดโลก ใช้ `at` เป็นข้อมูลประกอบ)
- **ตรวจความเสียหาย**: `validateSession` ตรวจโครงสร้างเหตุการณ์/เวลา/พิกัดของ interaction ก่อนใช้ทุกครั้ง
- **ทดสอบ**: ปุ่ม RUN TESTS (แท็บ Settings) มี "Interaction Recorder" ทดสอบตรรกะ + แถว "ได้รับเหตุการณ์จริง" เพิ่ม hold / tool / gui

### ไฟล์ V10.2 เดิม
ไม่ถูกแก้ไข/เขียนทับ — V10.5 (และ V10.4) เป็นไฟล์ใหม่ (`BALL_KUN_AI_FARM_V10_5.lua` + Loader ของมัน) ฐานข้อมูลใน `BALL_KUN_AI_Dump/` ใช้ร่วมกันได้และไม่ถูกเขียนทับ

## ส่วนที่ 4 — NPC Recorder (ใหม่ใน V10.4)
- **near / leave**: NPC (Model ที่มี Humanoid ไม่ใช่ผู้เล่น) เข้า-ออกรัศมี 30/36 สตั๊ด เช็กวินาทีละครั้ง พร้อมธง hasPrompt / hasClick / hasDialog
- **interact**: เมื่อผู้เล่นกด Prompt หรือคลิก ClickDetector ที่อยู่ใน NPC จะมีเหตุการณ์ `npc/interact` เพิ่ม (ต้องเปิด Interaction + สวิตช์ย่อยที่เกี่ยวข้องด้วย)
- สวิตช์ `NPC Recorder` เปิดปิดอิสระ (ปิด = ไม่มี near/leave/interact แต่ interaction ปกติยังบันทึกตามสวิตช์ของมัน)
- **ไม่ทำ**: ไม่คุย ไม่กด ไม่เดินเข้าหา NPC ไม่เรียก Remote
- **รายงาน AI**: สรุป NPC ที่พบ/โต้ตอบ (หมวดยืนยัน) และระบุว่า "เป็น NPC" ตัดสินจากโครงสร้าง (หมวดยังไม่ยืนยัน)
- ไฟล์ V10.2/V10.3 เดิมไม่ถูกแก้ ฐานข้อมูลไม่ถูกเขียนทับ

## ส่วนที่ 5 — Job Recorder v2 (ใหม่ใน V10.5)
ต่อยอดจาก Job Recorder เดิมของ V10.2 (ปุ่ม เริ่มภารกิจ / จบ + steps) **ไม่เขียนใหม่**: ปุ่มเดิม ลำดับ steps ลายเซ็นภารกิจ และ Farm Plan ทำงานเหมือนเดิม ข้อมูลใหม่เก็บแยกจาก steps เพื่อไม่ให้ปนกัน
(ขอบเขตส่วนนี้ดูจากช่องว่างของ Job Recorder เดิมในโค้ด ไม่ใช่จากสเปกที่ยืนยันแล้ว)

| เพิ่มอะไร | ทำอะไร | ที่มาของข้อมูล |
|---|---|---|
| marks | เหตุการณ์ระหว่างภารกิจ: นั่ง/ลงรถ, ตัวละครตาย, ค่า leaderstats เปลี่ยน, NPC near/leave/interact, ปล่อยปุ่มก่อนครบ (สูงสุด 200 ต่อภารกิจ) | ยืนยัน (เกม) ยกเว้น "ปล่อยก่อนครบ" = คำนวณฝั่งไคลเอนต์ (`calc=true`) |
| โน้ตขั้นตอน | ปุ่ม **จดโน้ต** จดขั้นตอนที่สคริปต์ตรวจจับไม่ได้ เก็บใน `notes` แยกจาก steps ไม่เข้าลายเซ็น/Farm Plan (สูงสุด 100 รายการ รายการละ 120 ตัวอักษร) | ผู้เล่นป้อน (`src="player"`) |
| ยกเลิกภารกิจ | ปุ่ม **ยกเลิกภารกิจ** สำหรับเริ่มผิด ไม่นับเป็นภารกิจ/ผล/แผน เหตุการณ์ดิบยังอยู่ใน events + มีบรรทัด `mission/cancel` เป็นหลักฐาน | ผู้เล่นกดเอง |
| กู้ภารกิจค้าง | ภารกิจที่ยังไม่จบถูกเก็บลง session ทุก Autosave (`activeMission`) ถ้าเกมปิดกลางคัน แล้ว START RECORDING ต่อด้วย ID เดิม ระบบกู้เป็นภารกิจ `result=unknown`, `interrupted=true` | ระบบ (ไม่เดาผล) |
| summary | ต่อภารกิจ: จำนวน/ประเภทขั้นตอน, ระยะเดิน (ต้องเปิด Movement), นั่งรถ, ตาย, ปล่อยก่อนครบ, NPC, โน้ต | คำนวณจากข้อมูลดิบ (Analyzer คำนวณใหม่ทุกครั้ง) |
| startPos / endPos | ตำแหน่งผู้เล่นตอนเริ่ม/จบภารกิจ | อ่านจากเกม |
| step.type | ขั้นตอนใหม่มีชนิด prompt/click/tool/gui (ข้อมูลเก่าอนุมานจาก action) | ยืนยัน (เกม) |

- **รายงาน AI**: เพิ่มหมวด "รายละเอียดภารกิจ" ต่อภารกิจ + "สรุปตามชื่อภารกิจ" (ทำกี่ครั้ง/สำเร็จ-ล้มเหลวที่ผู้เล่นป้อน/เวลาเฉลี่ย) แจ้งภารกิจไม่มีขั้นตอน, ภารกิจถูกตัดขาด, ชื่อเดียวกันแต่ลำดับต่างกัน (อยู่ในหมวด "ยังไม่ยืนยัน")
- **ตรวจความเสียหาย**: `validateSession` ตรวจเวลาเริ่ม/จบของภารกิจ, `steps/marks/notes` เป็นรายการและมีเวลาที่ถูกต้อง ข้อมูลรุ่นเก่า (ไม่มี marks/notes) ผ่านได้
- **หน้า Manual Learning**: บรรทัดสถานะภารกิจสด + ปุ่ม ยกเลิกภารกิจ + ช่อง/ปุ่ม จดโน้ต; Dashboard มีบรรทัดภารกิจ
- **ทดสอบ**: RUN TESTS มีแถว "Job Recorder v2" (ตรรกะ: steps/marks/notes/cancel/recover/summary/validate/Farm Plan/รายงาน)
- **ไม่ทำ**: ไม่รับ/จบภารกิจให้ ไม่กดปุ่ม ไม่เดิน ไม่เรียก Remote และไม่ตัดสินผลสำเร็จ/ล้มเหลวเอง (ยังมาจากผู้เล่นกด)

### ⚠️ พฤติกรรมที่เปลี่ยนจากเดิม (ตั้งใจ)
- ภารกิจที่ถูกตัดขาด (กด STOP ก่อนจบภารกิจ หรือกู้จากเกมปิด) ติดธง `interrupted` และ **ไม่ถูกนับเข้า Farm Plan / ความสอดคล้อง** เพราะลำดับไม่ครบ (เดิมถูกนับเข้า)
- `validateSession` เข้มขึ้นกับภารกิจ: session ที่ภารกิจมีเวลาจบก่อนเริ่ม หรือ marks/notes ไม่มีเวลา จะไม่ผ่าน (ข้อมูลเดิมที่ปกติไม่กระทบ)

### ข้อจำกัดที่ทราบ (ส่วนที่ 5)
- งานที่ไม่ใช้ Prompt/Click/Tool/ปุ่ม UI (เช่น ขับรถส่งของล้วน ๆ) จะได้ steps ว่าง — ได้เฉพาะ marks (นั่งรถ ฯลฯ) และโน้ต
- ภารกิจที่กู้: เวลาจบ = Autosave ล่าสุด (ทุก 30 วิ) ขั้นตอนหลังจากนั้นหายไป
- ระยะเดินในภารกิจต้องเปิด Movement Recorder ไม่เช่นนั้นแสดง "ไม่มีข้อมูล" (ไม่เดาเป็น 0)
- จดโน้ต/ยกเลิกภารกิจใช้ไม่ได้ตอน PAUSE (กด RESUME ก่อน) เพื่อไม่ให้เหตุการณ์หาย
- ยังไม่ได้รันในเกมจริง และยังไม่ผ่าน Luau parser — ดู TEST_REPORT_PART5.md
